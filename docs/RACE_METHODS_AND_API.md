# RACE 0.1 scientific and API contract

Research working-copy update: `race_config.selection_count` accepts an integer from 1 to 1000, default 20. This is a declared source selection cap, not a biological optimum or display limit. Source BH q ≤ 0.05 and the ranking rule are unchanged. The default retains method `brace-race/0.1.0`; a nondefault cap records `brace-race/0.2.0` in the frozen hypothesis and result. Frozen target testing rejects a different selection count. Comparisons after viewing target results are exploratory sensitivity analyses. See `docs/RESEARCH_FINAL.md` and `docs/quality/SCIENTIFIC_CHANGE_REGISTER.json`; historical example files and the original baseline hash register are preserved.

This is an additive backend capability. Existing Modes A/B/C, UI and historical evidence remain in place. All RACE results are exploratory, including runs whose manifests say independent_documented. User declarations do not authenticate acquisition. Only unpaired, unadjusted, two-condition processed log2 microarray designs are supported. Gene identifiers may be symbols, probe IDs or supported existing namespaces; the engine does not invent mappings or aggregate ambiguous probes. Numeric Entrez and unambiguous IDs are checked. Raw counts, other assay types, nonhuman organisms, repeated known patients, known patient/sample overlap, explicit pair IDs, paired/covariate designs, perfect study/class confounding and contradictory phenotype definitions block analysis. Missing donor IDs warn, rather than falsely certifying independence. Extreme declared log2 values outside ±1024 block with a scale error; this is a RACE-only numeric eligibility boundary, not a changed intake/API limit.

Source-only discovery accepts a source cohort and explicit condition definitions, not a target object. It screens the complete source feature family, not the source/target intersection. Source groups require at least two independent rows each; groups below ten warn. Known source dependence blocks. Target groups below two yield untestable selected hypotheses rather than manufactured p-values. Same-named phenotype labels need explicit shared biological definitions in `source_conditions` and `target_conditions`; these are user declarations, not automatic scientific authentication. Different assay processing requires `allow_processing_difference: true`, remains visible as a warning and does not enable direct scale comparison or model transfer.

For positive group a (n) and negative group b (m), the signed effect is Δ = mean(a) − mean(b). It is labeled a difference in deposited normalized log intensity, not log2 fold change. Sample variances use ddof=1. Welch SE² = sa²/n + sb²/m; t = Δ/SE; ν = SE⁴ / [(sa²/n)²/(n−1) + (sb²/m)²/(m−1)]. Two-sided p = 2·tν.sf(|t|). Pointwise CI = Δ ± tν,0.975·SE. These intervals are neither simultaneous nor corrected for source selection.

Hedges g = J(d)·Δ/sp, with d=n+m−2, sp²=[(n−1)sa²+(m−1)sb²]/d, and exact J(d)=Γ(d/2)/[sqrt(d/2)·Γ((d−1)/2)]. Pooled-SD standardization is descriptive under unequal variances; it is not proof of commensurate assays across studies. Any group with constant values is conservatively untestable, even if a numerical library returns an infinite statistic or a tiny floating variance. Undefined tests retain a reason. No imputation, renormalization, rescaling or variance regularization is applied.

BH is calculated as q(i)=min(1,min over j≥i of M·p(j)/j), mapped back to original IDs. All source features remain in M, including untestable hypotheses entered as p=1 only for correction (displayed p/q remain null). Select source q≤0.05, rank by decreasing |g| then lexicographic exact feature ID, take at most 20. Zero candidates is a valid result. Full source screen, selection status/rank, selected signs, source file hashes, family IDs, source manifest, settings and software versions are serialized and SHA-256 frozen **before** calculating target statistics. `selected_signature.json` is saved before target testing. JSON bytes are immutable; corruption is rejected. No target labels, values, availability, feature intersection or outcomes choose the source signature. The signature hash includes raw source file hashes, so equivalent reordered input files can have different provenance hashes while numerical results and selections remain equivalent.

Target uses the frozen features and same contrast. The target BH family is the entire frozen selected set; missing/untestable features enter correction as p=1 and remain explicitly unavailable. This is conservative and avoids outcome-dependent family reduction. The methods JSON records exact source and target family sizes. BH control assumes independent or suitably positively dependent tests; arbitrary gene dependence is not automatically controlled. There is no invented combined replication score.

Classifications are `supported_matching_direction` (target q≤0.05 and same nonzero effect sign), `opposite_direction` (opposite nonzero estimate, regardless of significance), `matching_direction_without_support`, `untestable`, or `indeterminate` (test defined but direction zero). Opposite-direction estimates are not necessarily statistically significant reversals. `not_statistically_supported` counts target-testable q>0.05 regardless of sign; it can overlap `opposite`. Direction fraction denominator is all target-testable selected genes; zero-effect indeterminate rows remain in that denominator. Empty denominator produces null. Nonsignificance never establishes no biological effect.

## HTTP use

`POST /api/race` accepts multipart fields `source_expression`, `source_metadata`, `source_manifest`, `target_expression`, `target_metadata`, `target_manifest`, and a JSON string form field `race_config`. Upload limits/extensions, fixed safe saved filenames, localhost/trusted hosts and origin checks are reused. Config is limited to 64 KiB; duplicate JSON keys and unsupported settings fail. Example config is `examples/public_er_pair/race_config.json`.

Response has `mode: race`, `kind: user_computed`, nested `race.eligible`, `race.status: completed_with_warnings`, `race.evaluation_role: exploratory`, and `race.validated_evidence_claim: false`. Failed scientific eligibility returns HTTP 422 with blocked status, eligible=false and issue records; failed run directories are removed. File-size violations retain HTTP 413. A user upload is not relabeled verified public data merely because it names a GEO accession. The scripted vetted example records `new_public_cohort_computation` in its separate verification record.

Reuse `GET /api/runs/{id}`, `GET /api/runs/{id}/export/race/{filename}` and `GET /api/runs/{id}/bundle`. Exports include the five allowlisted scientific files: `race_result.json`, `source_gene_screen.csv`, `selected_signature.json`, `replication_genes.csv`, `race_methods.json`. ZIP also contains a reproducibility manifest with artifact/input hashes, and excludes original uploads. CSV text starting with spreadsheet formula markers is quoted with a leading apostrophe; numeric signed effects remain numeric. JSON retains the exact original feature IDs. No new HTML rendering or executable model loading is introduced. Existing report generator is untouched; RACE has a separate small packaging function.

## Reproduce the public run

Install the existing `requirements.txt` in an isolated Python 3.11+ environment. From this application's root:

```
python scripts/run_public_race.py --out examples/public_er_pair/my_race_run
python -m pytest -q
python scripts/release_smoke.py
python verify_release.py
```

Choose a new output directory; the scientific writer refuses to overwrite a completed folder. Public runner checks preparation/raw hashes, repeats all five scientific outputs byte-for-byte and compares all defined source tests, target tests and source selection with a separate vectorized SciPy implementation. All 20 selected genes are retained regardless of target outcome. `race_final/` is the reviewed run; `verification.json` records actual runtime, discrepancies, provenance and aggregate counts. `gene_annotations.json` maps exact selected probe IDs to the pinned historic GPL570 symbols; those symbols are not claimed to be current independently validated nomenclature. No peak-memory, browser, user-study or startup-time claims were measured. See Pass 1B README for source filtering, patient/assay limitations, full exclusion ledgers, original downloads and reuse considerations.
