# Contributing and reporting issues

BRACE's own code is rights reserved. Opening the repository does not grant a general modification or redistribution licence. Discuss proposed contributions with the maintainer before substantial work; contributions must have clear ownership and compatible permissions.

For a bug, include the release/build version, operating system, exact task, expected behavior and observed error. Use a small artificial reproduction or public example. Do not attach private patient records, real uploads, credentials or unreviewed evidence exports.

Engineering changes must preserve scientific inputs/results and label historical, artificial and freshly computed evidence accurately. Run pytest and the scientific smoke check. Changes to scientific methods require explicit methodology review and must not be disguised as visual fixes. Never alter a regression test merely to hide a defect.

Browser automation is a developer tool, not a runtime dependency. Human usability, screen-reader and physical-device claims require actual evidence. Follow the existing Playful Precision verification principles recorded in the design and V6 acceptance documents.
